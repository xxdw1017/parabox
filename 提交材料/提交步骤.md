# 提交步骤（照这个顺序做）

## 第 0 步：材料推上 GitHub

材料在 `box/提交材料/`。VS Code 里 commit + Sync（或命令行 `git push`）即可，推送后仓库 HEAD 就是最终源工程。

## 第 1 步：把仓库改成公开

1. 打开 <https://github.com/xxdw1017/parabox> → 右上 **Settings**
2. 左侧 **General** → 拉到最底 **Danger Zone**
3. **Change repository visibility** → **Change visibility** → **Make public** → 弹窗里输入 `xxdw1017/parabox` 确认

**如果点了没反应**，按这个顺序排：① 退出登录再登录（GitHub 对改可见性要求 sudo 模式，会话过期会静默失败）；② 确认弹窗里输入的是 `xxdw1017/parabox` 全名而不是 `parabox`；③ 关广告拦截 + `Cmd+Shift+R` 硬刷新；④ 用 API 改（`curl -X PATCH ... '{"private":false}'`，需要 `repo` 权限的 token，命令见对话记录）。

**公开前自查（已确认）**：`.venv/` 未入库；无密码/密钥；仓库 2.6MB；`assets/` 的 logo 在 README 末尾有版权声明。

## 第 2 步：下载包名（组号确定后）

GitHub 的 `Code → Download ZIP` 名字是自动的 `仓库名-分支名.zip`（现在 `parabox-main.zip`），**改不了**。要得到课程要求的 `<组号>递归之箱.zip`：

1. 仓库右侧 **Releases** → **Draft a new release**
2. tag 填 `v1.0` → 标题填 `递归之箱（<组号>）`
3. 把下面第 3 步生成的 zip **拖进附件区** → **Publish release**
4. 提交栏里给 Release 链接（下载名就等于附件名）

## 第 3 步：生成 / 更新提交压缩包

```bash
.venv/bin/python 提交材料/打包提交材料.py                 # 输出 提交材料/递归之箱.zip
.venv/bin/python 提交材料/打包提交材料.py --name B01递归之箱  # 组号确定后带上组号
```

脚本会打印清单自检（视频 ✅ / PDF ✅ / exe ❌）。**还差 exe**：把 Windows 上打好的
`RecursiveBox.exe` 拷进 `提交材料/应用程序/`，再重跑一次脚本即可。

## 第 4 步：个人文档 PDF（已完成）

`提交材料/递归之箱_个人文档_董长坤.pdf` 已生成并校验：**A4、5 页、5 张插图、必备小节齐全**。

内容改动后重新生成（两个脚本同源，都跑一遍）：

```bash
.venv/bin/python 提交材料/生成个人文档HTML.py    # 打印版 HTML
.venv/bin/python 提交材料/生成个人文档PDF.py     # 直接出 PDF（推荐）
.venv/bin/python 提交材料/生成个人文档PDF.py --measure   # 只测每节是否超一页
```

> 若改用浏览器打印 HTML 导出 PDF：**纸张必须选 A4**（选 Letter 会挤成 6 页，之前那次就是这样）。
> 提示：正文里 `<!--pagebreak-->` 固定分 5 节，`--measure` 会逐节报高度，超页时按提示删几行。

## 第 5 步：发提交栏

用 `提交帖模板.md`：系统描述（298 字）+ 两张运行截图 + GitHub / Release 链接。

- [ ] 仓库已公开，匿名访问能看到代码
- [ ] Release `v1.0` 已发布，附件名符合 `<组号>递归之箱.zip`
- [ ] 包内五项齐全：源工程 / 应用程序 / 演示视频 / 汇报 PPT / 个人文档

- [ ] 提交栏：系统描述 ≤300 字、运行截图 1–2 张、链接可点开
- [ ] 在别的电脑验证过：下载 zip → 双击 exe 能进选关界面
