# 规则与测试的版本演化总览

本目录是课程要求里「**源工程（RULE.md、SKILL.md、AGENTS.md 及测试的多个版本）**」的逐版导出：
从 git 历史中把每个文件的**每一版内容**导出成独立文件，便于不熟悉 git 的人直接翻看。

统计：**9 个文件、共 31 个版本**（AGENTS.md 8 版 / RULE.md 3 版 / 4 份 SKILL 共 10 版 / 3 份测试共 10 版）。

> 说明：vN 按提交时间从早到晚编号；`导出文件` 列就是本目录下的实际文件名。
> 全部版本均可回溯到具体提交（短 hash 见下表），仓库克隆后 `git show <hash>:<文件>` 可复核。

## 一、三条主线（从版本差异里能直接看到）

**1. 口（door）模型：从"外挂方向字段"改成"由内层地图边缘决定"**

早期实现用 `exit_dir` / `entry_dir` 数据字段描述"从哪条边进出"，与地图脱节、表达力弱；
定稿改为：**内层宽高必须为奇数，四条边的中心格即口位，中心格是墙就没有口**，边缘环上除中心格外必须都是墙，
解析期即报错。这样"墙上的缺口就是门"，所见即所得，且箱子与玩家共用同一个口与落点（双向穿口 / 吞食）。
演进过程体现在 `level-loading`（3 版）与 `AGENTS.md`（8 版）的机制章节。

**2. 术语纠正：「动作逐层同步」→「同层链同步 + 跨层冻结」**

最初把机制写成"动作逐层同步"，容易被理解为"内层动作带动外层镜像更新"。定稿明确：
同步只发生在**同一层内**（整条箱链一起移动一格）；玩家进入内层后**外层完全冻结**，
实现中不存在跨层镜像同步。该术语已在 `AGENTS.md` 与 `nested-world` 技能中废弃并替换。

**3. 判定点：从"只有箱子目标点"扩展到"双条件判定"**

后来新增玩家站位目标点 `G`（整关最多一个，可放在任意一层）：通关 = **所有箱子目标点 `g` 被方块盖住**
**且玩家站上 `G`**。这次改动同时改了 `AGENTS.md`、两份 SKILL、关卡数据与三份测试（见 v2 版本），
是"规则先行、改一处同步三处"的典型例子。

**4. 美术定稿与"文档被测试守护"**

`world-rendering` 有 5 版：新增 `G` 的圆环标记 → 纯色平涂配色定稿（淡灰墙 / 深灰外层 / 深黄内部 /
洋红玩家 / 黄蓝方块）→ 去掉入口横线且判定点形状与玩家、方块等大 → 玩家加两只近黑小圆眼。
每改一次配色，测试都会要求**代码里的每个颜色都出现在技能文档中**、并满足对比度阈值。

**5. 关卡缺陷的修复痕迹**

`tests/test_logic.py` 从 v3 到 v4 记录了「吞食01」的一次真实修复：v3 加入该关卡（当时内层底边多了一个口），
v4 是"去掉误加的底边口，A 只留右侧一个口"——正是这次修正让关卡从 21 步可走的"隧道解"变成 37 步的
**必吞食解**。这条演化也对应汇报 PPT 里的"问题解决案例②"。

## 二、关于两个只有 1 版的 SKILL

`push-box-logic` 与 `nested-world` 各只有 1 版：这两份机制在动手编码前的规则讨论中一次定稿，
此后未再修改（其规则内容被 `AGENTS.md` 的 8 个版本、`RULE.md` 与测试版本反复引用与校验）。
如果要求"每个文件都体现演化"，可对照 `AGENTS.md` / `world-rendering` / `level-loading` / 三份测试
的多版本变化阅读，它们记录了同一套机制的定稿过程。

## 三、另有一次"改造 + 回退"

`AGENTS.md` v7/v8 与 `RULE.md` v2/v3 记录了一次**打包与投屏改造及其回退**：为在教室电脑上免安装运行，
曾引入 PyInstaller 打包链、云端构建与自检，随后按需回退。保留这两版是为了让历史完整、可追溯
（`git log` 中可见对应的 Revert 提交）。
