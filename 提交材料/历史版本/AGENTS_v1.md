# AGENTS.md

## 项目概述
Python + Pygame 复刻《Patrick's Parabox》单关卡。
核心机制：推箱子与箱子链、嵌套世界进出、跨层冻结、胜利判定。
单人开发，两周交付。本关实际只用 1 个带内部空间的箱子，但嵌套不设层级上限，算法一律按递归实现，便于后续扩展。

> 行为准则、修改前确认与交付检查见 `RULE.md`；机制细节一律查 `.dsh/skills/*/SKILL.md`，不得自行发挥。

## 技术栈
- Python 3.12（目标版本；本机实际用 3.13.12 运行，见 `.venv`）
- Pygame（绘制/事件/精灵/音效）—— 2.6.1，装在项目内 `.venv`
- unittest 单元测试
- Git 版本管理

## 运行命令
> 本机系统 Python（miniforge 基础环境）里**没有 pygame**，只有项目内 `.venv` 有。
> 直接 `python main.py` 会报 `ModuleNotFoundError: No module named 'pygame'`。
> 最省事的做法是先激活虚拟环境，之后再按下面的默认命令执行。

- 激活虚拟环境：`source .venv/bin/activate`
- 启动游戏：`python main.py`（激活后）；不激活则用 `.venv/bin/python main.py`
- 跑测试：`python -m unittest discover tests -v`（激活后）；不激活则用 `.venv/bin/python -m unittest discover tests -v`
- 只跑逻辑测试：`python -m unittest tests.test_logic -v`
- 用系统 Python 跑测试时，渲染 / 选关 / 主循环用例会自动跳过（未装 pygame），逻辑用例照常执行。
- IDE（VS Code）：解释器切到 `./.venv/bin/python`。

## 核心机制规则

### 世界与箱子的关系
- 世界是格子地图，箱子是占据格子的实体。
- 每个箱子可以携带一个 `inner_world`，内部世界也是格子地图。
- 箱子可以被推入另一个箱子的 `inner_world`，此时该箱子连同其 `inner_world` 整体成为外层箱子内部世界的一部分。
- **嵌套不设层级上限**：箱子进入任意层数的 `inner_world` 都合法，处于内部的箱子仍可携带自己的 `inner_world`。
  代码一律按递归处理，**禁止写死 2 层**（不得出现 `if depth >= 2: return` 之类的硬编码分支）。
- 唯一的硬性校验是**自引用**：禁止某个箱子的 `inner_world` 直接或间接地包含它自己，
  否则递归遍历/绘制会无限循环。本关数据不涉及，属于扩展关卡时的数据守卫。

### 同时推动规则
- 玩家推动方向上的连续箱子链，只要末端箱子前方为空地/目标点，整条链同时移动一格。
- 箱子链中任意一个箱子前方是墙或不可推动实体，整条链不移动。
- 箱子移动时，其 `inner_world` 不重新计算，只随箱子坐标平移。
- 整条链推不动时触发**吸入**：紧邻箱子的推动方向上**那条边有口**、且口上顶着推不开的箱子 B，
  则 B 连同 `inner_world` 被吸入该箱子的 `inner_world`，落点是该侧中心口格
  （这就是「再推一步，口把顶墙的箱子吸进去」）；不满足吸入条件则本步不产生任何移动。

### 进出与出口格（口由内层地图边缘决定）
- 内层世界的宽高必须是**奇数**，四条边的**中心格**就是口位；某条边有口 ⟺ 该中心格**不是墙**。
  边缘环上除四个中心格外必须都是墙 → **限制进出的是内层自己的边缘墙**，不是方向字段。
  四面全墙的箱子是合法数据，但进不去。
- **进入**：玩家站在箱子外侧朝箱子移动、箱子推不动，且这一侧的内层边缘有口；能推动就只推动、不进入。
  进入落点 = **对侧**那条边的中心口格（从下方推进去 → 落在内层底边的口，继续往里走）。
- **退出**：站在口格上朝该口的外侧方向走 → 退回外层，落点 = 外层箱子该侧的相邻格。
- 落点判定：是墙 → 出不去 / 推不动；有箱子 → 按推动规则推开（可连锁），推不开则整个动作无效。
- **箱子双向穿口**：外层推箱时，链尾箱子会被推进别人朝向它的口；内层推箱时箱子先被推到口格上，
  再推一步就推出到外层——与玩家用同一个口、同一个落点。
- 口格被箱子占住时，先把占位箱子朝房间内侧推一格；推不动则整个动作无效。
- 返回栈记录 `(world_ref, box_uid)`，退出时现查箱子位置，所以箱子被移动也不会算错出口。

### 同层链同步与跨层冻结
- “同步”只发生在**同一层内**：推动时整条箱子链同时移动一格。
- 玩家进入内层后，外层世界**完全冻结**：不响应输入、也不自行更新。
  实现里**没有**“内层动作带动外层箱子”的镜像同步（该机制原写作“动作逐层同步”，术语已废弃）。

### 胜利判定
- 判定范围是**所有层**：世界树里每一个目标点都被箱子盖住才算通关，实现在 `logic.check_win()` 一处。
- 玩家在哪一层不影响判定（可以在箱子内部通关）；level_01 的通关条件就是外层目标点与 `b1` 内部目标点都盖上。

## 代码约定
- 坐标统一用 `(x, y)` 元组表示格子坐标，不用像素坐标做逻辑。
- 世界状态用嵌套 dict 表示，层数由关卡数据决定，代码不写死层数；递归函数必须能处理任意深度。
- 所有移动/进出操作先走 `logic.py` / `nested.py` 的纯函数，再交给 `render.py` 绘制。
- 禁止在渲染层修改游戏状态。
- 新增关卡只改 `levels/*.json`，不改代码。

### 分层依赖规则
- **纯逻辑层**：`world.py`、`entity.py`、`logic.py`、`nested.py` 只依赖标准库，
  **禁止 import pygame**，保证推箱子规则与胜利判定可用 unittest 独立测试。
- **表现层**：`render.py`、`ui.py` 依赖 pygame，只读逻辑层状态，不修改状态。
- **驱动层**：`game.py` 负责主循环与场景状态机，串起逻辑层与表现层。
- 依赖方向单向：`main.py → game.py → logic/nested/world/entity`，表现层不得反向依赖。
- 素材路径统一在一处常量中定义，禁止在业务代码里硬编码相对路径。

### 文件命名约定
- 模块名小写下划线：`level_loader.py`；类名大驼峰：`class World`。
- 关卡文件：`levels/level_NN.json`；测试文件：`tests/test_<模块名>.py`。
- 每个 `src/` 模块配一个同名测试文件，新增模块时同步补测试。

## 开发约定
- **功能优先级**：必做 = 推箱子移动、嵌套世界进出、胜利判定、选关界面；
  选做 = 撤销/重置（已实现 U / R）、通关计时、简单音效。
- **深度策略**：本关只放 1 个带内部空间的箱子（实际 1 层）；实现按任意深度递归编写，
  单元测试至少覆盖 2 层嵌套与自引用守卫。
- **提交信息**：`<类型>: <简述>`，类型取 `feat` / `fix` / `test` / `docs` / `refactor` / `chore`。
- **测试要求**：改动 `src/` 下任何模块都要同步补 `tests/` 用例，
  运行方式 `python -m unittest discover tests -v`（渲染用例需 `.venv`）。
- **冻结节点**：9/14 功能冻结，之后只修 bug、补文档、录演示视频。

## 开发边界
- 不做关卡编辑器。
- 不为本关设计复杂多层谜题：只用 1 个带内部空间的箱子；引擎不写死层数，为后续扩展留口。
- 不引入 Pygame 以外的游戏引擎。
