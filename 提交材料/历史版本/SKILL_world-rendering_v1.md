# 多层世界渲染

## 视口与坐标
- 逻辑坐标一律是格子 `(x, y)`，渲染层负责换算成像素；**渲染层只读游戏状态，禁止修改**
  （RULE.md §一.8、AGENTS.md 分层依赖规则）。
- 窗口 1280×720，格子边长上限 `TILE = 64`；格子边长按
  `min(TILE, 可用宽 / 世界宽, 可用高 / 世界高)` 取整，保证小世界不放大、大世界不溢出。
- 只用 `pygame.draw` 画图，不引入贴图素材。

## 配色（取自 `assets/` 里的现有素材与两份汇报 PPT，不另行发明）
| 用途 | 色值 | 来源 |
|---|---|---|
| 页面底色 | `#111420` | 两份 PPT 的页面底色 |
| 地面 | `#1B2740` | 关卡示例图深蓝 `#16386B` 调暗，保证与墙有对比 |
| 墙 | `#3E7BB5` | 关卡示例图亮块 `#245B93` 提亮，保证与地面 ≥ 3:1 |
| 目标点 | `#6CC77A` | PPT 强调色（绿） |
| 玩家 | `#F5A623` | PPT 强调色（琥珀） |
| 箱子 | `#EBEEF5` 填充 | PPT 正文色 |
| 可进入标记 | `#BF0072` | logo / favicon 主色（品牌洋红） |
| 门（进出口） | `#7FB2FF` | PPT 链接色 |
| 正文 / 弱化 | `#EBEEF5` / `#98A2B8` | PPT 正文与次要文本色 |
| 面板 / 卡片 | `#1C2132` | PPT 卡片色（选关卡片、HUD 面板） |
| 警示（非法关卡） | `#FF6B6B` | PPT 强调色（红） |

## 绘制规则
1. 只画**当前活动世界**：以格子为单位画地面 / 墙 / 目标点，再画箱子、玩家。
2. 带 `inner_world` 的箱子，在其格子内缩 `max(2, tile×0.12)` 的矩形里**递归**画内层缩略图。
3. 缩略图把内层世界等比缩放到刚好放进该矩形（不拉伸、不超出、居中）；每深一层重复同样规则。
4. 缩略图的格子边长下限 `MIN_THUMB_TILE = 4`；低于该值时不再递归，只填一个色块（避免糊成一片）。
5. 每个箱子把它**有口的那几条边**画成缺口线（画在该边中心位置，用门色）；玩家在内层时，
   把当前活动世界的口格用门色描出来，让人一眼看见能从哪条边出去。
6. 活动层高亮：给当前活动世界的外框描 `#F5A623`；玩家所在层级用面包屑文字表示（如 `b1 › b1a`）。
7. HUD：关卡名、步数、操作提示；通关时叠半透明遮罩 + 通关文案与步数。

## 可读性硬指标（写成 unittest，改配色时必须仍然通过）
- 墙 vs 地面 ≥ 3.0:1（非文本大块的最低要求）
- 玩家 / 目标点 / 箱子 / 门 vs 地面 ≥ 4.5:1
- 正文 vs 底色 ≥ 4.5:1
- 可进入标记 vs 箱子填充 ≥ 3.0:1

## 验收方式
渲染是给人看的：**实现方看不到渲染结果时，任何配色 / 比例改动都要先出对照图再定稿**；
代码里只保证“对比度达标 + 几何不重叠 + 不改游戏状态”，观感由人眼确认。
