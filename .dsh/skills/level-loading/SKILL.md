# 关卡数据与加载校验

## 文件位置与命名
- 关卡放在 `levels/level_NN.json`；**新增关卡只加文件、不改代码**（RULE.md §四.4）。
- 加载入口：`world.load_level(path)` → `{"name", "title", "hint", "state"}`。

## 字段定义
```json
{
  "name": "level_01",
  "title": "递归之箱 · 第一关",
  "hint": "一句话提示",
  "world": {
    "w": 7, "h": 6,
    "tiles": ["#######", "#..g..#", "#.....#", "#.....#", "#..P..#", "#######"],
    "boxes": [
      { "uid": "b1", "at": [3, 3], "inner_world": { "...": "同结构，递归" } }
    ]
  }
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `world.w` / `world.h` | 是 | 宽高，均 ≥ 3；`tiles` 行数必须等于 `h` |
| `world.tiles` | 是 | 每行恰好 `w` 个字符 |
| `world.boxes[].uid` | 是 | 世界内唯一，非空字符串 |
| `world.boxes[].at` | 是 | `[x, y]`，必须在界内、不能是墙、不能与其他箱子或玩家起点重叠 |
| `world.boxes[].inner_world` | 否 | 内部世界，结构与本层完全相同，递归；**带它就有内部空间**（能不能进要看口） |

地形字符：`#` 墙、`.` 空地、`g` 目标点、`P` 玩家起点（每个世界最多一个，解析时转成空地）。

**已经没有方向字段**：`exit_dir` / `entry` / `entry_dir` 三个字段已废弃——口由内层地图边缘决定，
见下节。

## 内层世界的口规则（本模型的核心）
- **内层世界的宽高必须是奇数**（口在边的中心格上），否则解析报错。
- 四条边的**中心格**是口位：某条边有口 ⟺ 该中心格**不是墙**。
- **边缘环上除四个中心格外必须都是墙**，也就是“房间四面墙上最多各开一个居中的门”；
  别的位置开洞会报错，避免“半个口”的歧义。
- 四面全墙是**合法**数据（只是这个箱子进不去）。
- 口的位置决定进出方向：朝方向 `d` 进/出，走的是对侧那条边的中心口。

## 加载与校验
- 非法数据一律抛 `world.LevelError`，消息带出错位置，例如 `world.b1: 箱子不能放在墙上`。
- 校验清单（与 `parse_world` 实现一一对应）：宽高 ≥ 3；行列字符数与长度；未知字符；
  玩家起点唯一；`uid` 非空且世界内唯一；`at` 在界内、不是墙、不重叠、不压玩家起点；
  内层宽高为奇数；内层边缘除中心格外都是墙；整份关卡至少有一个目标点。
- **嵌套不设层数上限**；唯一的硬校验是自引用 / 循环嵌套（`world.validate_nesting()`），
  由 `nested` 在每次搬运后复查，出现则回滚该次操作。
- 选关界面遇到非法关卡不崩溃：`ui.list_levels()` 会把它标记为不可用并继续列出其余关卡。

## 测试要求
- 每条校验规则至少一个用例（见 `tests/test_world.py` 的 `TestParseErrors` / `TestDoors`）。
- 新增字段必须同步更新本文档 + 补用例 + 更新 `levels/level_01.json`。
